# Quran Content Policy

**Platform:** Tadabbur Al-Quran  
**Version:** 1.0  
**Effective Date:** 2026-04-24  
**Applies to:** All engineers, contributors, and AI tools working on this codebase

---

## Purpose

This platform presents Quranic content to a global Muslim audience. Errors in Quranic text, mis-attributed tafsir, or AI-fabricated religious explanations can cause serious harm. This policy establishes non-negotiable rules for how content is handled.

---

## Rule 1 — Arabic Quran Text Is Immutable

The Arabic text of the Quran (Uthmani rasm with diacritics) must never be:
- Modified manually in any file or database
- Corrected programmatically without a verified source and explicit sign-off
- Truncated, paraphrased, or altered in any display transformation

The canonical source is the Uthmani rasm as provided by api.alquran.cloud and stored in `data/raw/quran_uthmani.json`. Any discrepancy must be flagged and reviewed, not silently corrected.

---

## Rule 2 — Translation Must Be Labeled as Translation

English (or any non-Arabic) text rendered alongside an Arabic verse must be:
- Clearly labeled as a translation (e.g., "Translation: Sahih International")
- Never presented as if it is the Quran itself
- Never placed where a user could mistake it for the Arabic rasm

The `translator` field in the `translations` table must be displayed whenever translation text is shown. AI-generated translations must not be served to users. The `model_name` column must be NULL for all served translations.

---

## Rule 3 — Tafsir Must Come From Verified Sources

Tafsir and explanatory content must:
- Always be retrieved from the `tafseer_chunks` table, traced to a `TafseerSource` record
- Include the `source_id`, `chunk_id`, surah number, ayah number, author name, and tafsir title in every displayed explanation
- Never be generated by the model from general knowledge

Tafsir sources marked `license_verified = 0` or `status = "pending_user_input"` must not be displayed to end users until verification is complete.

---

## Rule 4 — RAG Answers Must Cite Sources

Every answer produced by the RAG pipeline must include:
- At least one verified citation (source title, author, surah, ayah)
- A confidence score
- Any applicable scholarly disagreement warnings

If no verified source is available for a question, the system must respond:

> "No verified source available for this answer."

This refusal message must not be removed, worked around, or softened without explicit product decision and documented justification.

---

## Rule 5 — The Model May Summarize but Not Invent

The LLM in the RAG pipeline may:
- Summarize and synthesize retrieved tafsir chunks
- Rephrase retrieved content for clarity
- Note that scholars differ on a question

The LLM must not:
- Invent a ruling, opinion, or explanation not found in the retrieved chunks
- Add theological commentary beyond what the sources say
- Issue a fatwa or definitive ruling on fiqh matters

The system prompt in `backend/app/rag/prompts.py` enforces this. Any modification to those prompts requires peer review.

---

## Rule 6 — Uncertainty Must Be Visible

When the system has low confidence in an answer, that uncertainty must be shown to the user — not hidden. This includes:
- Confidence scores below threshold (0.6 or lower)
- Scholarly disagreement between sources
- Answers grounded in fewer than two independent sources
- Any case where the model chose a minority opinion

Users must never receive an answer that appears certain when the underlying evidence is weak.

---

## Rule 7 — Islamic Tools Must Show Their Method

Tools such as prayer times, zakat calculation, and Islamic calendar must:
- Display the calculation method used (e.g., ISNA, MWL, Umm al-Qura)
- State any assumptions (e.g., angle used for Fajr, madhab for Asr)
- Link to the methodology documentation

These are religious obligations for users. Presenting incorrect values without disclosure of method is a harm.

---

## Rule 8 — RTL/LTR Text Must Not Be Mixed Incorrectly

Arabic text must always be rendered right-to-left (RTL). English text must be rendered left-to-right (LTR). Mixed content must use Unicode bidi controls or HTML `dir` attributes correctly.

Incorrect bidi rendering can distort the meaning of Quranic text and is prohibited.

---

## Rule 9 — No Silent Failures

If a source is missing, unavailable, or unverified, the system must say so explicitly. Silent failures include:
- Returning an answer without citing a source
- Displaying a source name without the `source_id` being verified
- Omitting the `needs_review` flag from the user interface

---

## Rule 10 — Content Changes Require Validation

Any change to content in these paths triggers a mandatory integrity validation run:
- `data/raw/`
- `data/manifests/`
- `data/concepts/`
- `backend/app/data/`
- `frontend/src/data/`
- `frontend/src/features/`
- `backend/app/api/routes/`

The validation command is: `npx tsx scripts/validate-quran-integrity.ts`

This must pass with zero errors before merging any content-related change.

---

## Enforcement

Violations of this policy should be treated as bugs, not style issues. PRs that:
- Display Quran text without source tracing
- Show tafsir without `source_id`
- Remove or weaken the safe-refusal behavior
- Generate religious content without retrieval

...will be blocked at review.
