## 2. Arabic Quran Text

**Storage:** Locally downloaded and stored in PostgreSQL (`quran_verses` table) and `data/raw/quran_uthmani.json`.

**Download tool:** `backend/scripts/datasets/download_quran.py` fetches from `https://api.alquran.cloud/v1/quran/quran-uthmani`.

**Local fields:**
- `text_uthmani` — Uthmani script with diacritics (displayed to users)
- `text_imlaei` — Imlaei script with diacritics
- `text_normalized` — Stripped diacritics for search indexing

**Integrity manifest:** `data/manifests/quran_hafs.json` specifies expected totals (6,236 verses, 114 surahs, 30 juz).

**Finding:** The Arabic text is fetched once and stored locally. It is NOT generated by AI at any point. The Uthmani rasm is the canonical form served to users.

**Risk:** No automated hash-verification of the stored text against the source after initial download. The `data_hash` field on `TafseerSource` exists but is not applied to `quran_verses`.

## 3. English Translations

**Primary source:** Sahih International via Tanzil.net (`https://tanzil.net/trans/en.sahih`).

**License:** Creative Commons BY-NC-ND 3.0 — non-commercial, no derivatives, attribution required.

**Storage:** PostgreSQL `translations` table with fields: `translator`, `language`, `text`, `model_name`, `checksum`, `confidence`, `needs_review`.

**AI translations:** The `Translation` model has a `model_name` column to flag LLM-generated translations. The `translation.py` service explicitly operates in SCHOLARLY mode, using only pre-verified translations. No AI translation is served at runtime for Quran verses.

**Finding:** Translation source is well-constrained. However, the `model_name` column exists, meaning LLM-generated translations may have been stored during development. Any row with `model_name IS NOT NULL` should be reviewed before production.

## 4. Tafsir (Quranic Exegesis)

**Storage:** PostgreSQL tables `tafseer_sources` (metadata + provenance) and `tafseer_chunks` (content, indexed for RAG).

**Provenance fields per source:**
- `cdn_url` — where fetched from
- `version_tag` — reproducible version identifier
- `retrieval_timestamp` — when data was fetched
- `data_hash` — SHA-256 integrity hash
- `license_type` / `license_verified` — legal compliance flags

**RAG pipeline:** All RAG answers are grounded exclusively in retrieved tafsir chunks. The `citation_validator.py` validates every citation against the retrieved evidence set before the response is returned. If evidence is insufficient, the pipeline returns a safe refusal.

**License gaps (requires action):**
- Al-Muyassar: `pending_user_input` — no license confirmed
- As-Sa'di: no source URL or license on file
- Tafheem-ul-Quran (Mawdudi): `pending_user_input`
- Ibn Kathir (EN) API: commercial use marked as `pending_user_input`

## 5. Stories, Concepts, Themes

**Stories (`data/manifests/stories.json`):** 122+ manually curated stories with verse references. Each story segment links to tafsir chunk IDs for evidence. No AI content — all narrative structure is human-authored.

**Concepts (`data/concepts/curated_concepts.json`):** Manually curated dictionary of Quranic persons, places, events, and attributes. Descriptions are brief and non-interpretive.

**Themes (`backend/app/data/themes/quranic_themes.json`):** Hierarchical taxonomy following Sunni Orthodox methodology (4 madhabs). Each theme entry links to tafsir sources. No AI-generated content.

**Finding:** All three are well-controlled locally. Risk is limited to curation accuracy, not AI generation.

---

## 6. UI and Source Visibility

**Current state:** The `SourcesPage.tsx` lists enabled tafsir sources with name, author, methodology, and reliability score. The `AskPage.tsx` shows citations inline within RAG answers. Source selector lets users pick which tafsir sources to query.

**Gaps:**
- Story cards do not display source attribution.
- Concept and theme detail pages do not show which tafsir sources were used for evidence.
- No standardized "source badge" component exists across the UI.
- No user-visible warning when a response has no verified source.
- License type and last-verified date are not shown to users anywhere.

## 8. Findings and Recommendations

### Critical (must fix before production)
1. Several tafsir sources have no confirmed license — do not display without verification.
2. No automated post-ingest hash check on Quran verses — add to validation pipeline.
3. UI does not warn users when a displayed answer has no verified source.

### Important (Phase 1 deliverables)
4. Add a source registry with structured metadata for all content sources.
5. Add a Quran integrity validation script runnable in CI.
6. Add source attribution badges to story, concept, and theme UI cards.
7. Add a content policy document.

### Informational
8. The `Translation.model_name` column should be audited; LLM-generated translations must not be served.
9. The RAG pipeline correctly refuses to answer without evidence — this behavior must be preserved.
10. Audio attribution (reciter, source, license) is not currently displayed to users.
