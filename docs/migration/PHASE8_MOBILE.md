# Phase 8: Android and iOS (Capacitor)

## Decision: Capacitor, not React Native

The app is a React/Vite SPA. It uses no browser-only APIs a WebView lacks: the microphone (`getUserMedia`), WebSocket, localStorage and fetch all work in Android WebView and WKWebView. Capacitor ships the existing build unchanged, so one codebase serves web, Android and iOS. A React Native rewrite would duplicate about 80 pages for no functional gain.

| | |
|---|---|
| Capacitor | 8.5.2 (`@capacitor/core`, `cli`, `android`, `ios`) |
| Plugins | `status-bar`, `keyboard`, `splash-screen`, `app` (Android back button) |
| App ID / bundle ID | `com.mhamdan.tadabbur` |
| App name | Tadabbur |
| Android | `frontend/android/`; minSdk 24, target/compile SDK 36; Gradle via the wrapper |
| iOS | `frontend/ios/`; iOS 15+, Swift Package Manager (no CocoaPods) |

## Production API URL: a build-time setting, NOT YET DECIDED

`VITE_API_URL` is compiled into the app bundle. It is a public address, never a secret; the HF token stays on the server. The template `frontend/mobile.env.example` carries the placeholder `https://REPLACE_WITH_PRODUCTION_API_HOST`.

| Build | Command | Rule (enforced in `vite.config.ts`) |
|---|---|---|
| Android/iOS release | `npm run build:mobile` | **Fails** if `VITE_API_URL` is unset, still the placeholder, not `https://`, or a loopback address |
| Android debug | `npm run android:debug` (`VITE_API_URL=http://10.0.2.2:8000` for the emulator) | Required, any scheme. HTTP is allowed only in the debug build (see network security) |
| Web | `npm run build` | `''` (same origin) or a public origin; loopback refused |

Verified (each build ran here):

| `VITE_API_URL` for `--mode mobile` | Result |
|---|---|
| unset | refused |
| `https://REPLACE_WITH_PRODUCTION_API_HOST` | refused |
| `http://localhost:8000` | refused |
| `https://127.0.0.1` | refused |
| `http://api.example.org` | refused |
| a well-formed `https://` origin | built; the origin is in the bundle |

The CI `mobile` job repeats the unset, placeholder and localhost cases on every push.

The backend's `CORS_ORIGINS` must include the WebView origins `https://localhost` (Android) and `capacitor://localhost` (iOS) in addition to the web origin.

## Platform configuration

- **No remote code.** `capacitor.config.ts` has no `server.url`; the app ships `dist/` inside the package.
- **Service worker.** The PWA service worker is disabled in mobile builds; it would only serve stale copies after an app update. The native shell mounts an offline-only banner instead of the update prompt.
- **Gzip copies.** Precompressed `.gz` files are not emitted for mobile builds. There is no nginx in the app, and Android's asset merger rejected `x.js` next to `x.js.gz` as duplicates; this broke the first APK build.
- **Network security (Android).**
  - Release: `cleartextTrafficPermitted="false"`, system CAs only, `allowMixedContent: false`.
  - Debug: a debug-source-set `network_security_config.xml` permits cleartext only to `10.0.2.2` and `localhost`.
  - Mixed content is allowed only when the debug sync sets `CAP_ALLOW_HTTP_BACKEND=true`.
  - Verified in the built APKs: the release APK has no cleartext domain; the debug APK lists exactly those two hosts.
- **App Transport Security (iOS).** No exceptions (no `NSAppTransportSecurity` key), so HTTPS only. iOS development therefore needs an HTTPS backend or tunnel.
- **Permissions.** Only the microphone is requested, at runtime, and only when the user starts a Tasmeeʿ recording.
  - Android: `RECORD_AUDIO`, `MODIFY_AUDIO_SETTINGS`, `android.hardware.microphone` with `required="false"`.
  - iOS: `NSMicrophoneUsageDescription` (English and Arabic).
  - Nothing else: no location, camera, storage or notifications.
- **Status bar and splash.** Brand blue `#0284c7` with light status-bar text; the splash screen hides once the app has mounted.
- **Keyboard.** `resize: body`, so the Ask and Search inputs stay above the keyboard.
- **Android back button.** Goes back in SPA history; at the root it exits the app.
- **Safe areas.**
  - `viewport-fit=cover`.
  - The sticky header pads by `safe-area-inset-top`.
  - The body pads by the left/right insets (landscape notch).
  - The floating "Report an Issue" button and the Mushaf and Surah Memory bottom sheets clear the home indicator.
- **Orientation.** Portrait and landscape (tablets); the PWA manifest says `any`.
- **Deep links.** Not configured: no feature needs them (no OAuth or email-link flows).
- **Icons and splash.**
  - Generated by `@capacitor/assets` from `frontend/assets/` (the same book glyph as the PWA icon).
  - Android: 74 files, including the adaptive icon. iOS: a 1024 px app icon and light/dark splash.
  - These are placeholders until the owner supplies brand artwork.

## Tasmeeʿ microphone: behaviour fixed and tested

The hook previously had no handling for interruptions. A WebSocket drop also left the microphone open.

**Now:**
- An OS-ended track (call, another app, permission revoked) or an iOS `interrupted` AudioContext stops recording and shows "Recording interrupted / Try again".
- Going to the background releases the microphone.
- A lost connection releases the microphone and shows "Connection lost".
- The permission-denied text on native points to device Settings instead of a browser lock icon.
- The record buttons gained accessible names.
- The timer stops whenever recording stops.

`frontend/e2e/tasmee-microphone.e2e.cjs` runs the same web code the WebViews run, in Chromium with a fake audio device, against the real backend:

| Scenario | Result |
|---|---|
| Permission denied (`NotAllowedError`, which Android WebView and WKWebView raise on "Don't allow") | "Microphone permission denied" with guidance; not recording |
| Permission granted | recording; 32 audio frames streamed in 3 s |
| OS interruption (track `ended`) | "Recording interrupted"; microphone released; record button back |
| Try Again, then app backgrounded | recording resumed; then paused with notice; microphone released |
| Backend drops the WebSocket (1011) | "Connection lost"; microphone released; not recording |
| HF speech recognition quota (`stt_unavailable` + close 4003) | "Speech recognition limit reached" notice kept; microphone released |

## Build verification (this VM: Ubuntu 24.04, JDK 21, Android SDK 36 installed from dl.google.com)

**Android, debug APK (G14, G15).**
- Command: `VITE_API_URL=http://10.0.2.2:8000 npm run android:debug`.
- Result: BUILD SUCCESSFUL. `app-debug.apk` is 6.1 MB.
- `aapt2` shows: package `com.mhamdan.tadabbur`, label Tadabbur, targetSdk 36, permissions `INTERNET` / `RECORD_AUDIO` / `MODIFY_AUDIO_SETTINGS`.
- The web assets and `capacitor.config.json` are in `assets/`, with no HF token or HF endpoint in the APK.

**Android, release APK.**
- Unsigned (`assembleRelease`): BUILD SUCCESSFUL, 4.6 MB.
- `allowMixedContent: false`; the network security config has no cleartext exception.
- Signing needs the owner's keystore, which is not in the repository.

**iOS (G16, G17).**
- `npx cap sync ios`: web assets and `capacitor.config.json` copied into `ios/App/App/public`.
- The Xcode project parses (`pbxproj`):
  - one `App` target
  - bundle ID `com.mhamdan.tadabbur` in Debug and Release
  - iOS 15 deployment target
  - all 11 file references resolve
  - the local SPM package `CapApp-SPM` exists
  - `Info.plist` parses, with the microphone string and no ATS exceptions
- **Native compile, signing and running: REQUIRES MACOS/XCODE.** None of this was attempted here.

**Machine-local workaround.** Maven Central returned HTTP 429 to this sandbox. Gradle used Google's Maven Central mirror through a user-level init script (`~/.gradle/init.d`), not through any file in the repository.

## Owner actions

1. Decide the production API origin. Put it in `frontend/.env.mobile` (git-ignored), or export `VITE_API_URL` in the build environment, and add `https://localhost,capacitor://localhost` to the backend `CORS_ORIGINS`.
2. Android release: create an upload keystore (kept outside the repo), configure signing, run `npm run android:release`, then upload to Play.
3. iOS: on macOS with Xcode 16+, run `npm run ios:sync`, then `npx cap open ios`. Set the signing team, archive and upload. Test the microphone prompt on a real device.
4. Replace the placeholder icon and splash in `frontend/assets/` with brand artwork, then run `npx capacitor-assets generate`.
